# 2. 详细设计

## 2.1 前端迭代目标

本次迭代实现薪资核算模块的全部前端页面。

**管理后台（AdminLayout）— 6 个页面：**

- 薪资管理：薪资账套、员工薪资、核算批次（含预览）、工资条管理、成本报表（5+1 页）

**员工门户（PortalLayout）— 1 个页面：**
- 我的薪资

**核心交互模式：** 列表页统一使用 `<ProTable>` 展示，表单使用 `<Modal>` / `<Drawer>`，状态使用标签组件着色，图表使用 `@ant-design/charts`，全局组件全部复用前端总系分封装。

### 2.2.4 工资条管理（管理端 + 员工端）

##### UI&交互

**管理端：** SearchBar（月份 + 部门 + 关键字）+ ProTable + 批量下发。

**员工端（`/portal/salary`）：** 近 6 月实发趋势 LineChart + 工资条列表 + 二次验证 Modal + PDF 下载。

##### 列表展示字段

| 字段名称 | 管理端 | 员工端 |
| --- | --- | --- |
| 员工姓名/工号 | ✅ | ❌（仅本人）|
| 部门 | ✅ | ❌ |
| 月份 | ✅ | ✅ |
| 应发/实发 | ✅ | ✅ |
| 发放状态 | ✅ | ✅（已发放）|
| 操作 | 查看详情 / 导出 PDF | 查看详情 / 下载 PDF |

##### 二次验证流程

```
点击「查看详情」
  → 判断是否有验证缓存（Redis hrms:payslip:verified:{userId} TTL 30min）
  → 无缓存 → 弹窗 PayslipVerifyModal → POST /profile/payslips/verify
  → 验证通过 → 缓存写入 30min → 展示 PayslipModal
  → 有缓存 → 直接展示 PayslipModal
```

> **注：** 规范路径为 `/profile/payslips/verify`，另有别名 `/auth/verify` 共用同一服务。`GET /profile/payslips/{period}` 详情须先验证，列表 `GET /profile/payslips` 无需验证。HR/财务端查看他人工资条走管理端接口 + 角色权限，无需二次验证。

##### 所需API

| 接口 | 说明 | 响应示例 |
| --- | --- | --- |
| `GET /payroll/payslips` | 管理端列表 | `{ "code": 0, "data": { "list": [{ "employeeId": 1, "employeeName": "张三", "period": "2026-07", "grossSalary": 15600.00, "netSalary": 12980.00, "status": "distributed" }], "total": 50 } }` |
| `GET /payroll/payslips/{month}` | 管理端详情 | `{ "code": 0, "data": { "period": "2026-07", "employee": { "name": "张三" }, "earnings": [], "grossSalary": 15600.00, "deductions": [], "netSalary": 12980.00 } }` |
| `GET /profile/payslips` | 员工端列表摘要 | 同上（SELF 范围） |
| `GET /profile/payslips/trend` | 近 6 月实发趋势 | `{ "code": 0, "data": [{ "period": "2026-07", "netSalary": 12980.00 }] }` |
| `GET /profile/payslips/{period}` | 员工端详情（须验证）| 同管理端详情 |
| `POST /profile/payslips/verify` | 二次验证 | `{ "code": 0, "data": { "verified": true } }` |
| `GET /profile/payslips/{period}/pdf` | PDF 下载 | 二进制文件流 |

// access.ts
export default function access(initialState) {
  const { permissions = [] } = initialState?.currentUser ?? {};
  const has = (code: string) => permissions.includes(code);
  return {
    canManagePayroll: has('payroll:manage'),
    canViewPayroll: has('payroll:view:all'),
    canViewPayrollBatch: has('payroll:batch:view'),
    canApprovePayroll: has('payroll:approve'),

}

## 5.4 数据刷新策略

使用 TanStack Query 管理服务端状态，提交/审批操作后 invalidate 对应缓存：

```typescript
const queryClient = useQueryClient();
// 核算操作后刷新
queryClient.invalidateQueries(['payroll-batches']);
queryClient.invalidateQueries(['payroll-details']);
// 工资条查看后刷新
queryClient.invalidateQueries(['payslip-list']);
```
